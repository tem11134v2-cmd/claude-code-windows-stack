# claude-code-windows-stack

Windows-сервер под Claude Code: агент работает в фоне, окружение настраивается один раз, наружу машина ходит одним IP. Разворачивается примерно за час, из которых ручных — минут пятнадцать.

Это боевая сборка, а не демо. Всё собрано по шишкам на реальных машинах.

**Статья с объяснением, почему именно так:** [`article/ARTICLE.md`](article/ARTICLE.md)

---

## Как запустить

На целевой машине открой Claude Code и дай ему этот промт:

```
Собери мне рабочую станцию под Claude Code на этом сервере.
Инструкция: https://raw.githubusercontent.com/tem11134v2-cmd/claude-code-windows-stack/main/README.md
Прочитай её целиком, начни со слоя 0 и сверяйся со мной после каждого шага.
```

Если `raw.githubusercontent.com` с машины не открывается — бывает за прокси и в закрытых сетях — скачай этот файл браузером и скинь Claude файлом. Дальше всё то же.

Читать самому тоже можно: каждый рецепт — обычный markdown с командами и таблицами.

## Claude: ты читаешь точку входа

**Что произошло.** Юзер дал тебе ссылку на этот файл — значит он собирает рабочую станцию с нуля или достраивает уже начатую. Твоя задача — провести его по слоям.

**Как брать остальные файлы.** Все пути ниже достраиваются к базе:

```
https://raw.githubusercontent.com/tem11134v2-cmd/claude-code-windows-stack/main/
```

Рецепт слоя 1 — это `<база>01-workstation/README.md`. Скрипты, на которые ссылаются рецепты, лежат там же по своему пути в репозитории: например `<база>03-projects/np.sh`.

> **Относительные ссылки внутри raw-файлов не работают.** Внутри рецептов ссылки написаны для человека, который смотрит репозиторий на GitHub. Ты всегда достраиваешь полный URL от базы выше.

**Порядок работы.**

1. Спроси юзера, с чего начинаем. Не знает — со слоя 0.
2. Забери рецепт этого слоя и прочитай **целиком** до первого действия. В шапке каждого рецепта написано, что именно от тебя ожидается, какие разделы ты проходишь сам и где возвращаешь управление.
3. Выполни слой, сверяясь с юзером после каждого шага.
4. В конце слоя есть блок проверки. **Прогоняет его юзер, не ты.** Дождись, пока он скажет, что вывод совпал с ожидаемым.
5. Переходи к следующему слою.

**Если упёрся в ошибку** — сначала `<база>TROUBLESHOOTING.md`, потом гугли. Там 37 кейсов, и многие симптомы выглядят не как их причина.

**Если юзер спрашивает «почему именно так»** — `<база>ARCHITECTURE.md`.

**Чего ты не делаешь — скажи юзеру и верни управление:**

- браузерная авторизация: `gh auth login`, вход в аккаунты сервисов;
- ввод паролей и лицензионных ключей;
- галочки в GUI — у Proxifier там половина критичных настроек;
- установка Git for Windows: мастер с десятком экранов, где одна неверная галка ломает всё через неделю;
- покупка VPS и прокси.

По каждому из этих пунктов продиктуй, что именно нажать и какие значения ввести, — но нажимает юзер.

**Главное ограничение, про которое помни сам.** Ты можешь отчитаться об успехе там, где успеха не было: команда вернула пустой вывод, ты счёл это нормой. Поэтому слой не считается пройденным, пока юзер не прогнал блок проверки и не подтвердил результат. Не предлагай пропустить проверку, даже если уверен.

**Голос:** коротко, по-русски.

## Что потребуется купить

| Компонент | Цена |
|---|---|
| VPS Windows — Timeweb Cloud | 4 000–8 000 ₽/мес |
| Статический резидентский прокси, 1 IP | ~$5/мес, **если нужен** |
| Proxifier Standard | $39.95 разово на машину, **если нужен прокси** |
| OpenRouter (только для слоя 3+) | от $5 по расходу |
| Cloudinary (только для слоя 3+) | бесплатный тариф |

Нужен ли прокси — развилка в начале слоя 0: на зарубежном сервере обычно нет, на дешёвом российском обязателен. Без прокси двух нижних строк в смете не будет.

**Потолок — две одновременные RDP-сессии.** Это ограничение лицензирования Windows Server, не настройки. Третьему человеку нужны CAL-лицензии или второй сервер.

## Безопасность

В этом репозитории **нет** секретов и не должно появиться. Ключи, пароли и профили прокси создаются на твоей машине и остаются на ней.

- `config.json` в `.gitignore` — коммитить его нельзя
- скрипты не хранят пароли: пароль запрашивается в момент выполнения
- профиль Proxifier (`.ppx`) экспортируешь себе сам, в репозиторий он не кладётся

Если будешь делать свой форк с секретами внутри — делай его приватным и помни, что история git сохранит их даже после удаления файла.
