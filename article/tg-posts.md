# Нарезка для Telegram

Шесть постов из статьи. Каждый самодостаточен — можно публиковать по одному в день или подряд.

Форматирование: Telegram не умеет таблицы, поэтому они развёрнуты в списки. Жирный — `**текст**`, код — обратные кавычки. Картинки прикрепляются к указанным постам, SVG предварительно конвертировать в PNG.

**Лимит Telegram — 4096 знаков.** Все посты ниже проходят с запасом.

## Пост 1 — Что это, сколько стоит и чего не умеет

**Картинка:** `assets/architecture.svg` → PNG

---

Вечером ставлю Claude Code задачу, отключаюсь от RDP, утром смотрю результат. Окружение собрано один раз, команда сидит в одной среде, ключи и проекты лежат на одной машине. Новый сервер поднимается примерно за час, из которых ручных — минут пятнадцать.

Дальше серия из шести постов: что купить, в каком порядке собирать и где я наступал на грабли. Всё боевое, не демо.

**Главная идея, если забрать из серии одну**

Я не иду по сорока шагам руками. Открываю Claude Code на свежей машине и скидываю ему файл-рецепт. В шапке файла написано, что от него ожидается: эти разделы прогони сам, вот здесь верни управление человеку — там браузерная авторизация. Дальше обычный markdown с командами, и Claude его **исполняет**: смотрит, что уже стоит на машине, пропускает лишнее, ставит недостающее.

Bash-скрипт на первом отличии машины падает. Claude адаптируется — а файл при этом остаётся читаемым, его можно открыть самому и вспомнить, что происходит на шаге 4.

Чего он не сделает: браузерную авторизацию, ввод паролей и ключей, галочки в GUI. И главное — **он может отчитаться об успехе там, где успеха не было**: команда вернула пустой вывод, он счёл это нормой. Поэтому каждый слой кончается блоком проверки, который прогоняешь ты сам.

**Ограничение, которое надо знать до покупки**

Одновременно на Windows Server работают **максимум две RDP-сессии**. Встроенный режим Remote Desktop for Administration даёт ровно две плюс консольную из панели провайдера. Третьему человеку нужна роль RD Session Host с лицензиями CAL либо второй сервер. Вся схема рассчитана на двух.

**Смета**

• VPS Windows, Timeweb Cloud — 4 000–8 000 ₽/мес
• Статический резидентский прокси, 1 IP — ~$5/мес, **если нужен**
• Proxifier Standard — $39.95 разово на машину, **если нужен прокси**
• OpenRouter для картинок — по расходу, ~$0.07 за картинку
• Cloudinary для CDN — бесплатный тариф
• Подписка на Claude — своя

Разброс 4–8 тысяч — разные уровни конфигурации, которые адекватно тянут Windows. Ниже четырёх тысяч Windows формально ставится, но RDP начинает отвечать с задержкой.

Плюс строка, которую забывают закладывать: **время на поддержку**. Час-два в месяц.

**Кому не нужно:** если Claude для тебя продвинутый автокомплит с ответом за десять секунд — не нужно. Схема окупается, только когда агент работает длинными автономными отрезками или когда людей больше одного.

## Пост 2 — Слой 0, часть первая: нужен ли прокси и какой сервер

**Картинка:** `assets/layers.svg` → PNG

---

Сборка делится на четыре слоя. Нулевой и первый обязательны, дальше по потребности.

Слой 0 начинается с развилки, которую надо решить **до** покупки сервера: от ответа зависит и локация, и ~$45 расходов, и половина работы.

**Нужен ли прокси**

• **Зарубежная локация у нормального провайдера** — не обязателен. IP уже зарубежный, статический и не засвеченный, для разработки этого достаточно.
• **Дешёвый российский VPS** — обязателен. IP у таких провайдеров приходят из пулов, которые часть нужных сервисов просто не пускает.
• **Российская локация у нормального провайдера** — по факту. Зайди и проверь, открывается ли то, с чем работаешь.

Я держу боевые машины на зарубежной локации без прокси, а на российских тестовых — с прокси. Если берёшь зарубежный сервер, Proxifier можно не ставить вообще, и слой 0 сводится к покупке и настройкам Windows.

**Если прокси нужен — какой**

Статический резидентский, один выделенный IP. Не ротационный, не датацентровый, не VPN.

• Static Residential — ротационный меняет IP каждые минуты и ломает любые залогиненные сессии: разлогины, 2FA на каждый чих
• Dedicated — IP только твой
• Без автоматических replacements — IP не должен меняться сам
• Протокол HTTPS, не SOCKS
• High IP reputation — брать, если есть за ~$1/мес

Не нужны: high concurrency, priority network, дополнительные IP. На выходе $5–7/мес.

Правила сервисов, которыми пользуешься, — на твоей ответственности. Я описываю сетевую часть, проверить ToS — твоя работа.

**Какой VPS**

Перебрал восемь провайдеров и остановился на **Timeweb Cloud** как на самом предсказуемом: Windows Server 2022 из шаблона прямо при заказе, есть и зарубежные локации, и российские, оплата любая, панель не падает. У остальных упирался в верификацию документом, в контракт на два года, в «Германию отдельно не выбрать» или в отсутствие Windows в шаблонах — на каждый такой вариант уходил вечер.

Конфигурация:

• Один человек + Claude Code — 4 vCPU, 8 ГБ
• Два человека, две сессии — минимум те же 4/8, комфортно 8 vCPU и 12+ ГБ
• Диск 80 ГБ NVMe хватает с запасом

При заказе: раздел Cloud Servers (не shared-хостинг), Windows Server 2022, публичный IP включён — без него не зайти по RDP, — ничего из managed-услуг. Срок месяц, на пробу.

## Пост 3 — Слой 0, часть вторая: Proxifier и настройки Windows

Пять шагов, порядок важен. Пропускаешь целиком, если по развилке из прошлого поста прокси не нужен.

**1. Добавить прокси.** `Profile → Proxy Servers → Add`: адрес, порт, Protocol HTTPS, галка Use authentication. Нажать **Check** и дождаться `Test passed`. Не пропускай Check — он ловит опечатку в пароле до того, как ты заворотишь в этот прокси весь трафик машины.

**2. Правило для всего трафика.** `Profile → Proxification Rules → Default rule → Edit → Action: Proxy HTTPS`.

⚠️ **Правило для localhost, которое стоит выше дефолтного, не трогать.** Оно единственное, что держит RDP-соединение. Завернёшь его в прокси — потеряешь доступ к серверу и будешь восстанавливать через консоль в панели провайдера. Самая дорогая ошибка слоя.

**3. Защита от утечек.** `Profile → Advanced`:
• DNS and IP Leak Prevention Mode — включить
• Bypass UDP Traffic → Block Traffic to All UDP Ports if Matched the Rule
• Block Non A/AAAA Queries if DNS through Proxy

Первая строка — kill switch: всё, что пытается пойти мимо прокси, блокируется на уровне сетевого стека. Блокировка UDP закрывает утечки через WebRTC и QUIC.

**4. DNS через прокси.** `Profile → Name Resolution → Resolve hostnames through proxy`. Без этого IP у тебя будет чужой, а DNS-запросы — свои, и это видно.

**5. Автозапуск.** `Settings → Start with Windows` и `Hide on close`. Второе важнее, чем кажется: без него Proxifier однажды закроется крестиком, и машина останется без защиты ровно до того момента, как ты это заметишь.

**Настройки Windows — четыре вещи**

• **Электропитание.** `Power Options → High performance`, в расширенных настройках Hard disk / Sleep / Display → Never. Иначе ночью сервер заснёт вместе с твоей задачей.
• **Таймауты RDP.** `gpedit.msc → ... → Remote Desktop Session Host → Session Time Limits`, все три пункта в Disabled. Третий, про disconnected sessions, — самый важный: именно он отвечает за то, чтобы отключённая сессия и запущенные в ней задачи продолжали жить.
• **Обновления** — Pause updates на максимум, чтобы не перезагрузило посреди работы.
• **Часовой пояс** — та зона, в которой реально работаешь. Таймзона попадает в логи, в даты коммитов и в расписания задач, и когда через месяц разбираешь, почему ночная задача отработала «не тогда», неверная зона стоит час жизни.

Системный язык — английский. Не из эстетики: текст ошибки на английском гуглится, на русском нет.

**Проверка слоя**

Перезагрузить сервер. Дальше `ifconfig.me` — самый «голый» сервис, показывает ровно тот IP, с которого пришёл запрос. Именно так тебя видит любой сайт. Если используешь прокси, добавить `whoer.net`, `browserleaks.com/webrtc` (должно быть No Leak) и `dnsleaktest.com`.

⚠️ Если хоть один тест показывает не тот IP или утечку — слой не пройден. Не иди дальше: всё, что поставишь сверху, будет ходить наружу неправильным путём.

## Пост 4 — Слой 1: рабочее место

На выходе: git, gh, Scoop, mise, SSH-ключ и Claude Code, который видит bash. Полчаса-час, активных — минут десять, остальное качается.

**Руками — ровно две вещи**, и обе потому, что это мастера с галочками.

**Git for Windows.** В мастере есть один экран, который определяет, будешь ли ты через неделю разбираться с загадочной ошибкой:

• **Line ending conversions → «Checkout as-is, commit Unix-style line endings»** (вторая опция)
• Default editor — Notepad, не Vim
• Default branch — `main`
• PATH — средняя, рекомендованная опция
• SSH — bundled OpenSSH
• Extra options — включить symbolic links

Строка про line endings — это `core.autocrlf = input`. Оставишь дефолт — все `.sh` в проектах получат CRLF, и любой скрипт упадёт с `bad interpreter: /usr/bin/env bash^M`. Ошибка выглядит как мистика, а причина — галка, которую щёлкнул неделю назад.

**GitHub CLI** — обычный `.msi`, Next → Install → Finish.

После обоих — **полностью перезапустить Claude Code**: трей → Quit, проверить в диспетчере, что процесса нет, открыть заново. Иначе он не увидит свежий PATH.

**Остальное делает Claude:** Scoop, mise, vcredist, `.bashrc`, git identity, SSH-ключ, переменная `CLAUDE_CODE_GIT_BASH_PATH`. Один раз остановится и попросит сходить в Git Bash за `gh auth login`, продиктовав ответы на каждый вопрос мастера.

Node и pnpm глобально **не ставятся** — приезжают per-project через `.tool-versions` в репозитории. Два проекта на разных версиях Node живут рядом и не конфликтуют, а новый человек получает ровно ту версию, на которой проект собирали.

**Две грабли этого слоя**

⚠️ **Никогда не писать `eval "$(mise activate bash)"` в `.bashrc` на Windows.** Команда возвращает PATH с разделителями `;` вместо `:`, и Git Bash перестаёт находить вообще всё — `git`, `ls`, `which`. Выглядит как «сломалась система», а это одна строка в конфиге. Правильный путь — добавить каталог shims в PATH руками.

**Режим `auto`, а не `bypassPermissions`.** Хотелось, чтобы Claude Code не спрашивал разрешение на каждую правку. Но `bypassPermissions` в десктопной версии спонтанно откатывается на более строгий режим сразу после первого сообщения — это известные issue в трекере Anthropic, помеченные «not planned», то есть чинить не будут. `auto` чуть консервативнее, но не сбрасывается.

**Проверка:** `git --version`, `gh auth status`, `mise --version`, `mise doctor` (внизу «No problems found»).

Строка `shims_on_path: no` в выводе `mise doctor` — **не ошибка**. У mise два режима активации, и в shims-режиме этот пункт всегда `no`. Я на неё в своё время потратил полчаса.

## Пост 5 — Слой 2: второй пользователь и один Proxifier на машину

Самая неочевидная часть всей схемы — пришлось разбираться экспериментально.

Слой нужен, только если на сервере будет работать больше одного человека, или если хочешь отделить рабочую учётку от административной: под `Administrator` со временем накапливается всё — история Claude Code, проекты, бэкапы, мусор экспериментов, — и перенос на новую машину становится миграцией «всё или ничего».

Напомню потолок: **две одновременные сессии, больше не будет.** Разные учётки получают свои сессии из коробки, групповых политик для этого менять не надо.

**Один Proxifier на машину**

Proxifier Standard — single-instance приложение: одна копия на весь компьютер. Отсюда три следствия:

• **Профиль настраивается под каждым пользователем, одинаково.** Профиль хранится per-user, а заранее не известно, кто зайдёт первым.
• **Кто первым залогинился — у того Proxifier и запустился**, и через его профиль идёт трафик всей машины.
• **У второго автозапуск выдаст «another instance is already running». Это нормально** — закрываешь крестиком и работаешь, трафик уже защищён первым инстансом.

Чтобы один инстанс действительно ловил всех, нужны две галки — и они не в самом меню Advanced, а в отдельном диалоге `Profile → Advanced → Services and Other Users...`, который там половина людей не находит:

• Applications run by other users on this computer
• Windows services and other system processes

Без них Proxifier перехватывает трафик только своего пользователя, а второй ходит в интернет напрямую. Это тихая утечка — её не видно, пока не проверишь специально.

**Про админские права, раз уж тут все про них спрашивают.** Перехват работает на уровне драйвера: Proxifier Standard ставит WFP-callout драйвер, один на машину. Права администратора нужны ровно на его установку, то есть один раз при инсталляции. Дальше запущенному GUI они не требуются. В моём рецепте рабочий пользователь всё равно попадает в `Administrators`, но это для удобства — ставить софт и лазить в `gpedit`, — а не требование Proxifier.

**Лицензия на всех.** `Help → Registration`: при вводе ключа обязательно поставить галку **«for all users of this computer»**, тогда лицензия уходит в машинную ветку реестра и видна всем, включая пользователей, которых создашь потом. Без галки каждый новый видит триал.

**Одно поведенческое правило**

⚠️ **Из RDP выходить крестиком (Disconnect), а не через Start → Sign out.**

Disconnect оставляет сессию живой — вместе с ней живёт Proxifier и продолжают работать фоновые задачи. Sign out убивает сессию целиком, и если это была та, чей Proxifier защищал остальных, появится окно, в котором трафик второго пользователя идёт напрямую.

Правило стоит повесить на видное место для всех, кто пользуется сервером: оно неочевидно и легко нарушается на автомате.

**Проверка:** под вторым пользователем `(Invoke-RestMethod https://api.ipify.org?format=json).ip` должен показать IP прокси, а не сервера.

## Пост 6 — Слой 3, что в схеме плохо и репозиторий

**Новый проект одной командой.** Рутина «создать репозиторий, склонировать, поставить нужную версию Node, поставить зависимости, разрешить сборку нативных модулей» — шесть команд, в которых легко ошибиться порядком. В репозитории лежит скрипт с тремя сценариями: новый проект из своего шаблона, клон своего существующего, клон чужого репозитория.

Три вещи, которые стоит знать и без скрипта:

• `.env.production` в `.gitignore` — после клона проект работает в fallback-режиме, секреты для прода надо забрать отдельно
• Публичный SSH-ключ новой машины надо добавить в `authorized_keys` деплой-пользователя, иначе не выкатить
• Прописать каждому проекту свой порт в `package.json` сразу — иначе два дев-сервера начнут играть в чехарду, и через неделю не вспомнишь, кто где

**Картинки: два своих MCP-сервера.** Генерация через OpenRouter — готовые MCP обычно требуют прямого биллинга у Google (Cloud, Vertex AI), а за пределами США это отдельный квест; OpenRouter принимает карты, PayPal и крипту, API один на все модели. Цены за картинку: Nano Banana 2 — $0.07 (мой дефолт, хорошо рендерит текст внутри картинки), Nano Banana 1 — $0.04 на черновики, GPT-5.4 Image 2 — $0.22 на обложку, когда нужен максимум.

Схемы к этой серии, кстати, нарисованы не ими: генеративные модели пока не умеют технические диаграммы с правильными подписями.

Публикация — в Cloudinary, одним вызовом с готовым набором ссылок под разные места: обложка, баннер, мобильная версия, превьюшка, карточка для соцсетей. Бесплатного тарифа (25 ГБ хранения и трафика) на контентный сайт хватает надолго.

**Что в этой схеме плохо**

• **Windows дороже и тяжелее Linux.** Та же конфигурация на Linux стоит в два-три раза меньше и не требует RDP. Windows здесь ровно потому, что Claude Code Desktop — GUI-приложение. Устраивает CLI — Linux будет лучше по всем параметрам. Это самая серьёзная претензия к схеме.
• **RDP — единственная дверь.** Отвалился RDP — ты слеп, остаётся медленная консоль в панели провайдера.
• **Два человека — потолок.** Третьему нужны CAL-лицензии или второй сервер.
• **Мультипользовательский режим Proxifier — обходной путь.** Штатный стоит дороже и называется Service Edition.
• **Прокси — единая точка отказа.** Лёг прокси — встала вся машина. Обратная сторона kill switch: он честно защищает и честно останавливает.
• **Режим `auto` — не то, что хотелось.** Изредка останавливается и спрашивает, и если это в два часа ночи, задача ждёт до утра.

**Репозиторий**

Все рецепты, скрипты и сводный TROUBLESHOOTING на 35 кейсов:
