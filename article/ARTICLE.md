# Claude Code на своём сервере

### Windows-сервер, на котором агент работает ночью, окружение настроено один раз, а наружу машина ходит одним IP

---

Вечером ставлю Claude Code задачу, отключаюсь от RDP, утром смотрю результат. Окружение собрано один раз, команда сидит в одной среде, ключи и проекты лежат на одной машине. Новый сервер поднимается примерно за час, из которых ручных — минут пятнадцать: бо́льшую часть делает сам Claude по файлу, который я ему скидываю.

Дальше — инструкция по шагам. Обоснования решений и все грабли, на которые я наступал, вынесены в репозиторий (ссылка в конце) — в статье их не будет, иначе она превратится в мемуары.

**Кому это не нужно:** если Claude для тебя продвинутый автокомплит с ответом за десять секунд — не нужно. Схема окупается, только когда агент работает длинными автономными отрезками или когда людей больше одного.

---

## Что получается

![Архитектура: один исходящий IP на всю машину](assets/architecture.svg)

На машине сколько угодно пользователей и программ, но наружу она ходит ровно одним путём. Один инстанс Proxifier перехватывает трафик обеих RDP-сессий и системных служб. Прокси недоступен — трафик останавливается, а не идёт напрямую.

Исключение одно: само RDP-подключение идёт мимо прокси. Это не недосмотр, а необходимость — в слое 0 будет отдельное предупреждение, ошибка там дорогая.

> ⚠️ **Ограничение, которое надо знать до покупки: одновременно на Windows Server работают максимум две RDP-сессии.**
>
> Встроенный режим Remote Desktop for Administration даёт ровно две, плюс консольную из панели провайдера. Третьему человеку нужна роль RD Session Host с лицензиями CAL — отдельные деньги и отдельная настройка — либо второй сервер. Вся схема ниже рассчитана на двух.

Сборка делится на четыре слоя. Нулевой и первый обязательны, дальше по потребности: нужен сервер только под себя — проходишь 0, 1, 3 и пропускаешь 2.

![Четыре слоя](assets/layers.svg)

У каждого слоя есть граница «готово» и блок проверки — несколько команд с ожидаемым выводом.

## Инструкцию исполняет Claude

Я не иду по сорока шагам руками. Открываю Claude Code на свежей машине и даю один промт:

```
Собери мне рабочую станцию под Claude Code на этом сервере.
Инструкция: https://raw.githubusercontent.com/tem11134v2-cmd/claude-code-windows-stack/main/README.md
Прочитай её целиком, начни со слоя 0 и сверяйся со мной после каждого шага.
```

Дальше он читает точку входа, забирает оттуда рецепт нужного слоя и идёт по нему. В шапке каждого рецепта написано, что от него ожидается:

> **Claude: это рецепт первоначальной настройки чистого Windows-сервера. Юзер скинул тебе этот файл — значит хочет, чтобы ты провёл его через установку.** Прогони §1–§2 сам, запрашивая разрешения когда нужно. В §3 верни управление юзеру — там браузерная авторизация. Если что-то ломается — §6 Troubleshooting.

Дальше идёт обычный markdown с командами и таблицами. Claude его **исполняет**: смотрит, что уже стоит на машине, пропускает лишнее, ставит недостающее, останавливается там, где нужен человек. Bash-скрипт на первом отличии машины падает — Claude адаптируется, а файл при этом остаётся читаемым: его можно открыть самому и вспомнить, что происходит на шаге 4.

**Чего он не сделает:**

- `gh auth login` — браузерная авторизация с одноразовым кодом;
- ввод паролей и лицензионных ключей;
- галочки в GUI — у Proxifier половина критичных настроек там;
- установку Git for Windows — мастер с десятком экранов, где одна неверная галка ломает всё через неделю.

**И главное: он может отчитаться об успехе там, где успеха не было.** Не из вредности — команда вернула пустой вывод, он счёл это нормой. Поэтому каждый слой заканчивается блоком проверки, который прогоняешь ты сам.

**Почему ссылкой, а не клоном репозитория.** Очевидный вариант — склонировать репо и читать файлы локально — на нулевом слое не работает: на чистом Windows Server нет ни `git`, ни `gh`, их ставит первый слой. Курица и яйцо. Поэтому точка входа отдаётся по raw-ссылке, а внутри неё лежат абсолютные ссылки на остальные файлы — относительные из raw-файла не разрешаются. Если `raw.githubusercontent.com` на машине не открывается — бывает за прокси — скачай README браузером и скинь файлом, дальше всё то же.

## Слой 0. Сервер и сеть

**На выходе:** сервер куплен и доступен, весь трафик идёт одним путём, утечек нет.
**Время:** 1–2 часа.

### Сначала развилка: нужен ли прокси

От ответа зависит и локация, и $45 расходов, так что решается до покупки.

| Сервер | Прокси |
|---|---|
| **Зарубежная локация** у нормального провайдера | **Не обязателен.** IP уже зарубежный, статический и не засвеченный — для разработки этого достаточно |
| **Дешёвый российский VPS** | **Обязателен.** IP у таких провайдеров приходят из пулов, которые часть нужных сервисов просто не пускает |
| **Российская локация** у нормального провайдера | По факту. Зайди и проверь, открывается ли то, с чем работаешь, — и решай по результату |

Я держу боевые машины на зарубежной локации без прокси, а на российских тестовых — с прокси. Если берёшь зарубежный сервер, следующие два раздела можно пропустить целиком: Proxifier не нужен, слой 0 сводится к покупке и настройкам Windows, а проверка — к одному тесту `ifconfig.me`.

### Если прокси нужен — какой

**Статический резидентский, один выделенный IP.** Не ротационный, не датацентровый, не VPN.

| Параметр | Значение | Почему |
|---|---|---|
| Тип | Static Residential | Ротационный меняет IP каждые минуты — ломает любые залогиненные сессии: разлогины, 2FA на каждый чих |
| Exclusivity | Dedicated | IP только твой |
| Replacements | без автоматических | IP не должен меняться сам |
| Protocol | **HTTPS** | не SOCKS |
| High IP reputation | взять, если ~$1/мес | меньше капч там, где их быть не должно |

Не нужны: high concurrency, priority network, дополнительные IP. Цена на выходе — $5–7/мес.

Важная оговорка при покупке: у многих провайдеров «Residential» в названии тарифа означает **ротационный** пул, а нужный продукт лежит отдельной строкой как «Static Residential». Разница в цене небольшая, разница в поведении — принципиальная.

После оплаты в панели провайдера получишь четыре значения: IP, порт, логин, пароль. **Это секрет** — не в репозиторий, не в открытые чаты, не в документы, которыми делишься по ссылке.

Правила сервисов, которыми пользуешься, — на твоей ответственности. У многих в условиях есть пункты о том, откуда можно подключаться; проверить ToS — твоя работа, не моя.

### Какой VPS

**Timeweb Cloud.** Я перебрал восемь провайдеров и остановился на нём как на самом предсказуемом: Windows Server 2022 ставится из шаблона прямо при заказе, есть и зарубежные локации, и российские, оплата любая, панель не падает. У остальных упирался в верификацию документом, в контракт на 24 месяца, в «Германию отдельно не выбрать» или в отсутствие Windows в шаблонах.

Конфигурация под задачу:

| Что делает машина | Минимум | Комфорт |
|---|---|---|
| Один человек, только браузер | 2 vCPU, 4 ГБ | 4 vCPU, 8 ГБ |
| Один человек + Claude Code | 4 vCPU, 8 ГБ | 4 vCPU, 8 ГБ |
| Два человека, две RDP-сессии | 4 vCPU, 8 ГБ | 8 vCPU, 12+ ГБ |

Диска 80 ГБ NVMe хватает с запасом. При заказе: раздел Cloud Servers (не shared-хостинг), ОС Windows Server 2022, публичный IP включён — без него не зайти по RDP, — и ничего из managed-услуг. Срок на пробу — месяц.

### Первый заход

Через 5–10 минут после оплаты в панели появятся IPv4, логин `Administrator` и одноразовый пароль. Зайти по RDP и сразу:

1. Сменить пароль — `Ctrl+Alt+End` → Change password. Длинный.
2. Скачать Chrome через Edge.
3. Скачать Proxifier с официального сайта (если он нужен) — Standard Edition, триал 31 день.

### Proxifier: пять шагов

Установка обычная, Next → Install. Дальше порядок важен.

**1. Добавить прокси.** `Profile → Proxy Servers → Add`: адрес, порт, Protocol **HTTPS**, галка Use authentication с логином и паролем. Нажать **Check** и дождаться `Test passed`. Не пропускай Check — он ловит опечатку в пароле до того, как ты заворотишь в этот прокси весь трафик машины.

**2. Правило для всего трафика.** `Profile → Proxification Rules → Default rule → Edit → Action: Proxy HTTPS [твой прокси]`.

> ⚠️ **Правило для localhost, которое стоит выше дефолтного, не трогать.** Оно единственное, что держит RDP-соединение. Завернёшь его в прокси — потеряешь доступ к серверу и будешь восстанавливать через консоль в панели провайдера. Самая дорогая ошибка слоя 0.

**3. Защита от утечек.** `Profile → Advanced`:

| Настройка | Значение |
|---|---|
| **DNS and IP Leak Prevention Mode** | ✓ включить |
| Bypass UDP Traffic | → **Block Traffic to All UDP Ports if Matched the Rule** |
| Block Non A/AAAA Queries if DNS through Proxy | ✓ |

Первая строка — kill switch: всё, что пытается пойти мимо прокси, блокируется на уровне сетевого стека. Блокировка UDP закрывает утечки через WebRTC и QUIC.

**4. DNS через прокси.** `Profile → Name Resolution → ✓ Resolve hostnames through proxy`. Без этого IP у тебя будет чужой, а DNS-запросы — свои, и это видно в тестах.

**5. Автозапуск.** `Settings → ✓ Start with Windows`, `✓ Hide on close`. Второе важнее, чем кажется: без него Proxifier однажды закроется крестиком, и машина останется без защиты ровно до того момента, как ты это заметишь.

### Настройки Windows

Четыре вещи, без которых фоновая работа ночью не работает.

| Что | Где | Значение |
|---|---|---|
| **Электропитание** | `Control Panel → Power Options → High performance → Change advanced power settings` | Hard disk / Sleep / Display → **Never** |
| **Таймауты RDP-сессий** | `gpedit.msc → Computer Configuration → Administrative Templates → Windows Components → Remote Desktop Services → Remote Desktop Session Host → Session Time Limits` | все три пункта → **Disabled** |
| **Обновления** | `Settings → Windows Update → Advanced options` | Pause updates на максимум |
| **Часовой пояс** | `Settings → Time & Language` | та зона, в которой реально работаешь |

Про таймауты: третий пункт, «Set time limit for disconnected sessions», — самый важный. Именно он отвечает за то, чтобы отключённая сессия (а вместе с ней Proxifier и твои фоновые задачи) продолжала жить после того, как ты закрыл RDP.

Про таймзону: она попадает в логи, в даты коммитов и в расписания задач. Когда через месяц разбираешь, почему ночная задача отработала «не тогда», неверная таймзона стоит час жизни.

Системный язык — английский. Не из эстетики: текст ошибки на английском гуглится, на русском нет.

### Чего не делать

Четыре вещи, каждая из которых стоила мне отдельного вечера.

**Не логиниться в рабочие аккаунты, пока Proxifier не настроен.** IP машины попадёт к ним в логи как твой обычный адрес входа, и потом каждая смена IP будет вызывать подтверждения.

**Не работать с упавшим Proxifier.** Иконка в трее неактивна — значит трафик идёт напрямую. Kill switch из шага 3 это закрывает, но смотреть на иконку всё равно стоит: это полсекунды.

**Не брать обычный VPN вместо резидентского прокси.** NordVPN, ProtonVPN и прочие дают датацентровые IP из общих пулов: зашарены на тысячи людей, половина в чёрных списках, и ты получаешь капчи там, где их быть не должно.

**Не менять локацию прокси после настройки.** Смена страны рвёт все залогиненные на сервере сессии — получишь разлогины и повторные подтверждения по всему списку сервисов сразу. Локация выбирается один раз.

### Проверка слоя 0

Перезагрузить сервер, дождаться полной загрузки, убедиться, что иконка Proxifier в трее активна. Дальше:

| Тест | Что должно быть |
|---|---|
| `ifconfig.me` | тот IP, который ты ожидаешь увидеть наружу |
| `whoer.net` | IP, страна и провайдер — те, что у прокси |
| `browserleaks.com/webrtc` | WebRTC Leak Test: **No Leak**, поля Local IP и Public IP пустые |
| `dnsleaktest.com` → Standard test | DNS-серверы в той же стране, что прокси, посторонних нет |

`ifconfig.me` — самый «голый» сервис: показывает ровно тот IP, с которого пришёл запрос. Именно так тебя видит любой сайт. Если прокси не используешь, этого теста достаточно.

> ⚠️ **Если хоть один тест показывает не тот IP или утечку — слой не пройден.** Не идти дальше: всё, что поставишь сверху, будет ходить наружу неправильным путём, и чинить это потом сложнее.

Эта проверка разовая, при сборке. Дальше, перед началом работы, хватает двух пунктов: иконка Proxifier в трее активна и `ifconfig.me` показывает ожидаемый IP. Десять секунд, и дальше можно не думать.

## Слой 1. Рабочее место

**На выходе:** git, gh, Scoop, mise, SSH-ключ и Claude Code, который видит bash.
**Время:** 30–60 минут, активных — минут десять. Остальное качается.

### Руками — две вещи

**Git for Windows.** В мастере есть один экран, который определяет, будешь ли ты через неделю разбираться с загадочной ошибкой:

| Экран | Что выбрать |
|---|---|
| **Line ending conversions** | **«Checkout as-is, commit Unix-style line endings»** — вторая опция |
| Default editor | Notepad (не Vim) |
| Default branch name | `main` |
| PATH environment | средняя опция, рекомендованная |
| SSH executable | bundled OpenSSH |
| Extra options | ✓ Enable symbolic links |

Строка про line endings — это `core.autocrlf = input`. Если оставить дефолт, все `.sh` файлы в проектах получат CRLF, и любой скрипт упадёт с `bad interpreter: /usr/bin/env bash^M`. Ошибка выглядит как мистика, а причина — галка, которую щёлкнул неделю назад.

**GitHub CLI.** Обычный `.msi`, Next → Install → Finish.

После обоих — **полностью перезапустить Claude Code**: трей → Quit, проверить в диспетчере задач, что процесса нет, открыть заново. Иначе он не увидит свежий PATH.

### Остальное делает Claude

Scoop, mise, vcredist2022, `.bashrc`, git identity, SSH-ключ, переменная `CLAUDE_CODE_GIT_BASH_PATH`, вспомогательный скрипт для создания проектов. Один раз остановится и попросит сходить в Git Bash за `gh auth login`, продиктовав ответы на каждый вопрос мастера.

Node и pnpm на машину глобально **не ставятся** — они приезжают per-project через `.tool-versions` в репозитории. Два проекта на разных версиях Node живут рядом и не конфликтуют, а новый человек получает ровно ту версию, на которой проект собирали.

### Две грабли этого слоя

> ⚠️ **Никогда не писать `eval "$(mise activate bash)"` в `.bashrc` на Windows.** Эта команда возвращает PATH с разделителями `;` вместо `:`, и Git Bash перестаёт находить вообще всё — `git`, `ls`, `which`. Выглядит как «сломалась система», а это одна строка в конфиге. Правильный путь — добавить в PATH каталог shims руками; готовый `.bashrc` лежит в репозитории.

**Режим `auto`, а не `bypassPermissions`.** Хотелось, чтобы Claude Code не спрашивал разрешение на каждую правку файла. Но `bypassPermissions` в десктопной версии спонтанно откатывается на более строгий режим сразу после первого сообщения — это известные issue в трекере Anthropic, помеченные «not planned», то есть чинить не будут. Режим `auto` чуть консервативнее, но не сбрасывается.

### Проверка слоя 1

```
git --version        → git version 2.5x.x.windows.x
gh auth status       → Logged in to github.com, Active account: true
mise --version       → 2026.x.x windows-x64
mise doctor          → внизу «No problems found»
```

Строка `shims_on_path: no` в выводе `mise doctor` — **не ошибка**. У mise два режима активации, и в shims-режиме этот пункт всегда `no`. Я на неё в своё время потратил полчаса.

## Слой 2. Второй пользователь

**На выходе:** второй пользователь со своей RDP-сессией, его трафик тоже под прокси.
**Время:** 15 минут.

Нужен, только если на сервере будет работать больше одного человека — или если хочешь отделить рабочую учётку от административной. Под `Administrator` со временем накапливается всё: история Claude Code, проекты, бэкапы, мусор экспериментов, и перенос на новую машину становится миграцией «всё или ничего».

Напомню про потолок: **две одновременные сессии, больше не будет.** Разные учётки получают свои сессии из коробки, никаких групповых политик для этого менять не надо.

### Один Proxifier на машину — как это работает на практике

Это самая неочевидная часть схемы, и мне в своё время пришлось разбираться экспериментально.

Proxifier Standard — single-instance приложение: одна копия на весь компьютер. Отсюда три следствия:

- **Настраивать профиль надо под каждым пользователем, одинаково.** Заранее не известно, кто зайдёт первым, а профиль Proxifier хранится per-user.
- **Кто первым залогинился — у того Proxifier и запустился**, и через его профиль идёт трафик всей машины.
- **У второго автозапуск выдаст ошибку «уже запущено в другой сессии». Это нормально**, закрываешь крестиком и работаешь: трафик уже защищён первым инстансом.

Чтобы один инстанс действительно ловил всех, нужны две галки — и они не в самом меню Advanced, а в отдельном диалоге `Profile → Advanced → Services and Other Users...`, который там половина людей не находит:

- ☑ **Applications run by other users on this computer**
- ☑ **Windows services and other system processes**

Без них Proxifier перехватывает трафик только своего пользователя, а второй ходит в интернет напрямую. Это тихая утечка — её не видно, пока не проверишь специально.

Про админские права, раз уж тут все про них спрашивают: перехват работает на уровне драйвера — Proxifier Standard ставит WFP-callout драйвер, и он один на машину. Права администратора нужны ровно на его установку, то есть один раз, при инсталляции. Дальше запущенному GUI они не требуются. В моём рецепте рабочий пользователь всё равно попадает в `Administrators`, но это для удобства — ставить софт и лазить в `gpedit`, — а не требование Proxifier.

### Лицензия на всех пользователей

`Help → Registration`. При вводе ключа **обязательно поставить галку «for all users of this computer»** — тогда лицензия уходит в машинную ветку реестра и видна всем, включая пользователей, которых создашь потом. Без галки каждый новый видит триал.

Лицензия Standard покрывает две машины, активируется на каждой отдельно.

### Одно поведенческое правило

> ⚠️ **Из RDP выходить крестиком (Disconnect), а не через Start → Sign out.**

Disconnect оставляет сессию живой — вместе с ней живёт Proxifier и продолжают работать фоновые задачи. Sign out убивает сессию целиком, и если это была та сессия, чей Proxifier защищал остальных, появится окно, в котором трафик второго пользователя идёт напрямую.

Правило стоит повесить на видное место для всех, кто пользуется сервером: оно неочевидно и легко нарушается на автомате.

### Проверка слоя 2

Зайти под вторым пользователем:

```
(Invoke-RestMethod https://api.ipify.org?format=json).ip   → IP прокси, не сервера
ssh -T git@github.com                                       → Hi <login>! You've successfully authenticated
```

Первая команда главная. Если под вторым пользователем она показывает IP сервера — перехват чужих пользователей не работает, слой не пройден.

## Слой 3. Проекты и инструменты

**На выходе:** новый проект разворачивается одной командой, подключены MCP для генерации и публикации картинок.
**Время:** 2–10 минут на проект.

### Новый проект одной командой

Рутина «создать репозиторий, склонировать, поставить нужную версию Node, поставить зависимости, разрешить сборку нативных модулей» — шесть команд, в которых легко ошибиться порядком. В репозитории лежит скрипт с тремя сценариями: новый проект из своего шаблона, клон своего существующего, клон чужого репозитория, куда тебя позвали коллаборатором.

Три вещи, которые стоит знать и без скрипта:

**Что не приезжает вместе с git.** `.env.production` в `.gitignore` — после клона проект работает в fallback-режиме, секреты для прода надо забрать отдельно. И публичный SSH-ключ новой машины надо добавить в `authorized_keys` деплой-пользователя, иначе выкатить не получится.

**Ограничения режима коллаборатора.** Прямой push в основную ветку обычно закрыт защитой — работа через ветки и pull request. Доступа к секретам окружения владельца не будет.

**Порты.** Когда на машине несколько проектов, два параллельных дев-сервера начинают играть в чехарду: 3000 занят, беру 3001. Через неделю уже не помнишь, кто где. Прописать каждому проекту свой порт в `package.json` сразу.

### Картинки: два MCP-сервера

**Генерация — через OpenRouter.** Готовые MCP для картинок обычно требуют прямого биллинга у Google: Cloud, Vertex AI, настройка платёжного аккаунта. За пределами США это отдельный квест. OpenRouter принимает карты, PayPal и крипту, кредиты не сгорают, API один на все модели.

| Модель | Цена | Когда беру |
|---|---|---|
| Nano Banana 2 | $0.07 | дефолт на каждый день, хорошо рендерит текст внутри картинки |
| Nano Banana Pro | ~$0.14 | сложные композиции, обычно возвращает сразу два варианта |
| Nano Banana 1 | $0.04 | черновики |
| GPT-5 Image mini | $0.04 | самый дешёвый у OpenAI |
| GPT-5 Image | $0.18 | узнаваемая «чатгпт-эстетика» |
| GPT-5.4 Image 2 | $0.22 | обложка, когда нужен максимум |

Схемы к этой статье, кстати, нарисованы не ими: генеративные модели пока не умеют технические диаграммы с правильными подписями. Генерация хороша для обложек и иллюстраций.

**Публикация — в Cloudinary.** У Cloudinary есть официальный MCP на два десятка инструментов, но мне нужен был ровно один сценарий — «загрузи картинку и верни готовую ссылку», — а в официальном инструменте загрузки был баг с путями на Windows. Свой сервер делает один вызов и возвращает набор ссылок под разные места: обложка, широкий баннер, мобильная версия, превьюшка, карточка для соцсетей, аватарка. Все с автоформатом, то есть современный браузер получит WebP или AVIF, а старый JPEG.

Бесплатного тарифа (25 ГБ хранения и 25 ГБ трафика в месяц) на контентный сайт хватает надолго.

Оба сервера ставятся одной командой через `uv` и подключаются правкой конфига MCP-клиента. Готовые блоки конфига — в репозитории.

## Что в этой схеме плохо

**Windows дороже и тяжелее Linux.** Та же конфигурация на Linux стоит в два-три раза меньше, грузится быстрее и не требует RDP. Windows здесь ровно потому, что Claude Code Desktop — GUI-приложение. Устраивает CLI-версия — Linux-сервер будет лучше по всем параметрам. Это самая серьёзная претензия к схеме.

**RDP — единственная дверь.** Отвалился RDP — ты слеп. Остаётся консоль в панели провайдера: работает, но медленно и неудобно.

**Два человека — потолок.** Третьему нужны CAL-лицензии или второй сервер.

**Мультипользовательский режим Proxifier — обходной путь.** Попап «уже запущено» у второго пользователя работает, но штатный режим стоит дороже и называется Service Edition. Если у вас реально два активных человека каждый день — это правильная покупка, которую я отложил.

**Прокси — единая точка отказа.** Лёг прокси — встала вся машина. Обратная сторона kill switch: он честно защищает и честно останавливает. Резервного канала нет осознанно — автопереключение на запасной IP ломает всё, ради чего это затевалось.

**Режим `auto` — не то, что хотелось.** Изредка останавливается и спрашивает, и если это случилось в два часа ночи, задача будет ждать до утра.
