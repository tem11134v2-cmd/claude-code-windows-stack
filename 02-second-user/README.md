## Зачем это вообще

Под `Administrator` со временем накапливается всё: история Claude Code, проекты, бэкапы, мусор экспериментов. Перенести это на новую машину — миграция «всё или ничего». Отдельная рабочая учётка даёт чистый старт, ничего не ломая.

Вторая причина важнее и менее очевидна — она про утечку трафика, см. §2.

Полное обоснование — в [`../ARCHITECTURE.md`](../ARCHITECTURE.md).

## §1. Создать пользователя

**Под администратором.**

```powershell
Copy-Item "<путь>\02-second-user\config.example.json" "<путь>\02-second-user\config.json"
notepad "<путь>\02-second-user\config.json"
```

Поправить `user.name`, `paths.projects` и при необходимости `proxifier.profilePath`.

**Пароля в конфиге нет намеренно** — скрипт спросит его при выполнении и нигде не сохранит.

```powershell
powershell -ExecutionPolicy Bypass -File "<путь>\02-second-user\scripts\01-create-user.ps1"
```

Что делает: создаёт локального пользователя, добавляет в `Administrators` и `Remote Desktop Users`, выдаёт права на папку проектов. Идемпотентно — если пользователь уже есть, просто доберёт недостающие права.

> ⚠️ Пароль должен проходить политику сложности Windows: минимум 8 символов, заглавные, строчные и цифры. Чисто цифровой будет отклонён с невнятной ошибкой.

### Про админские права — чтобы снять вопрос

Скрипт добавляет рабочего пользователя в `Administrators`. **Это для удобства, а не требование Proxifier:** рабочему пользователю надо ставить софт и лазить в `gpedit`, и без админа он будет упираться в это каждый день.

Перехват чужого трафика админских прав у GUI не требует. Proxifier Standard работает через WFP-callout драйвер, один на машину; права администратора нужны ровно на его установку — то есть один раз, при инсталляции Proxifier в слое 0.

Хочешь более жёсткую изоляцию — можешь оставить рабочего пользователя обычным и добавить только в `Remote Desktop Users`. Я этот вариант не обкатывал, так что готовься разбираться по ходу.

## §2. Proxifier: один инстанс на машину

Это самая неочевидная часть всей схемы. Proxifier Standard — single-instance приложение: одна копия на весь компьютер. Отсюда три следствия.

**1. Профиль настраивается под каждым пользователем, одинаково.** Профиль Proxifier хранится per-user (`%APPDATA%\Proxifier4\Profiles`), а заранее не известно, кто зайдёт первым. Поэтому прогоняешь настройку дважды — либо экспортируешь `.ppx` из первой учётки и импортируешь во вторую (это умеет делать скрипт `02-proxifier.ps1`).

**2. Кто первым залогинился — у того Proxifier и запустился**, и через его профиль идёт трафик всей машины.

**3. У второго автозапуск выдаст «another instance is already running». Это нормально** — закрыть крестиком и работать: трафик уже защищён первым инстансом. Проверить:

```powershell
(Invoke-RestMethod https://api.ipify.org?format=json).ip
```

### Галочки перехвата

**Только руками, в GUI.** Под каждым пользователем, чей Proxifier может запуститься первым:

`Profile → Advanced → Services and Other Users...`

Это **отдельный диалог**, а не галки прямо в меню — их там часто не находят. Внутри включить:

- ☑ **Applications run by other users on this computer**
- ☑ **Windows services and other system processes**

Без них Proxifier перехватывает трафик **только своего пользователя**, и второй ходит в интернет напрямую. Это тихая утечка — её не видно, пока не проверишь специально ([`../TROUBLESHOOTING.md`](../TROUBLESHOOTING.md), N1).

### Лицензия на всех пользователей

`Help → Registration`

Если Proxifier просит ключ — ввести и **обязательно поставить галку «for all users of this computer»**. Тогда лицензия уходит в машинную ветку реестра и видна всем, включая пользователей, которых создашь потом. Без галки каждый новый пользователь видит триал.

Лицензия Standard покрывает две машины; на каждой активируется отдельно.

## §3. Под новым пользователем

Зайти по RDP под новым пользователем. Дальше всё оттуда.

```powershell
powershell -ExecutionPolicy Bypass -File "<путь>\02-second-user\scripts\02-proxifier.ps1"
```

Что делает: копирует профиль `.ppx` (если указан в конфиге) и прописывает автозапуск Proxifier при входе.

> ⚠️ Если увидишь попап **«уже запущено в другой сессии»** — это нормально, закрой крестиком. Твой трафик защищён тем инстансом, который стартовал первым.

Дальше под этим пользователем повторить слой 1 — у него своё окружение: свой `.bashrc`, свой SSH-ключ, своя авторизация в GitHub.

## §4. Одно поведенческое правило

> ⚠️ **Из RDP выходить крестиком (Disconnect), а не через Start → Sign out.**

**Disconnect** оставляет сессию живой. Вместе с ней живёт запущенный Proxifier и продолжают работать фоновые задачи.

**Sign out** убивает сессию целиком. Если это была та сессия, чей Proxifier защищал остальных, появится окно, в котором трафик второго пользователя идёт напрямую.

Правило стоит повесить на видное место для всех, кто пользуется сервером. Оно неочевидно, и его легко нарушить на автомате.

## §5. Проверка слоя

Под **новым** пользователем:

```powershell
(Invoke-RestMethod https://api.ipify.org?format=json).ip
```

→ должен вывести IP прокси, **не** IP сервера из панели провайдера.

Это главная проверка слоя. Если показывает IP сервера — значит `Applications run by other users` не работает, и слой не пройден. Причины — в [`../TROUBLESHOOTING.md`](../TROUBLESHOOTING.md).

```bash
ssh -T git@github.com
```

→ `Hi <login>! You've successfully authenticated...`

Дополнительно: зайти в обе RDP-сессии одновременно и проверить IP в каждой. Обе должны показывать прокси.
