## §1. Развилка: нужен ли прокси

Решается **до** покупки сервера: от ответа зависит и локация, и ~$45 расходов, и половина этого рецепта.

| Сервер | Прокси |
|---|---|
| **Зарубежная локация** у нормального провайдера | **Не обязателен.** IP уже зарубежный, статический и не засвеченный — для разработки этого достаточно |
| **Дешёвый российский VPS** | **Обязателен.** IP у таких провайдеров приходят из пулов, которые часть нужных сервисов просто не пускает |
| **Российская локация** у нормального провайдера | По факту: зайти, проверить, открывается ли то, с чем работаешь, и решить по результату |

**Если прокси не нужен:** пропускаешь §2 и §5, в §7 прогоняешь только первый тест. Слой сводится к покупке и настройкам Windows.

**Если нужен:** читаешь дальше по порядку. Прокси берётся **до** сервера — учётные данные понадобятся уже на первом часу.

## §2. Прокси

*Пропустить, если по §1 прокси не нужен.*

### Что именно нужно

**Статический резидентский прокси, один выделенный IP.** Не ротационный, не датацентровый, не VPN.

| Параметр | Значение | Почему |
|---|---|---|
| Тип | Static Residential | Ротационный меняет IP каждые минуты — ломает залогиненные сессии |
| Exclusivity | Dedicated | IP только твой, не шарится |
| Replacements | без автоматических обновлений | IP не должен меняться сам |
| Bandwidth | Unlimited (fair use) | у разработки трафик небольшой, но считать его утомительно |
| Protocol | **HTTPS** | не SOCKS |
| Auth | Username / Password | |
| High IP reputation | взять, если есть за ~$1/мес | IP не в чёрных списках — меньше капч |

Не нужны: high concurrency, priority network, дополнительные IP.

**Цена ориентировочно $5–7/мес.**

### Оговорка при покупке

У многих провайдеров «Residential» в названии тарифа означает **ротационный** пул, а нужный продукт лежит отдельной строкой как **Static Residential**. Разница в цене небольшая, разница в поведении — принципиальная. Проверять до оплаты.

### Что получишь

После оплаты в панели провайдера — четыре значения: `IP`, `порт`, `логин`, `пароль`. Они пойдут в Proxifier на каждой машине.

> ⚠️ **Эти четыре значения — секрет.** Не класть в репозиторий, не пересылать в открытых чатах, не вставлять в документы, которыми делишься по ссылке.

### Оговорка

Правила сервисов, которыми пользуешься, — на твоей ответственности. У многих в условиях есть пункты о том, откуда и как можно подключаться. Этот рецепт описывает сетевую часть; проверить ToS своих сервисов — твоя работа.

## §3. VPS

### Чем брать

**Timeweb Cloud** — самый предсказуемый из тех, что я перебрал. Windows Server 2022 ставится из шаблона прямо при заказе, есть и зарубежные локации, и российские, оплата любая.

**Цена: 4 000–8 000 ₽/мес** — разброс по уровням конфигурации, которые адекватно тянут Windows. Ниже четырёх тысяч Windows формально ставится, но RDP начинает отвечать с задержкой.

У остальных провайдеров упирался в верификацию документом, в минимальный контракт на два года, в «Германию отдельно не выбрать» или в отсутствие Windows в шаблонах — на каждый такой вариант уходил вечер.

### Конфигурация под задачу

| Что делает машина | Минимум | Комфорт |
|---|---|---|
| Один человек, только браузер | 2 vCPU, 4 ГБ | 4 vCPU, 8 ГБ |
| Один человек + Claude Code | 4 vCPU, 8 ГБ | 4 vCPU, 8 ГБ |
| Два человека, две RDP-сессии | 4 vCPU, 8 ГБ | 8 vCPU, 12+ ГБ |

Диск: 80 ГБ NVMe хватает с запасом.

> ⚠️ **Потолок — две одновременные RDP-сессии.** Встроенный в Windows Server режим Remote Desktop for Administration даёт ровно две, плюс консольную из панели провайдера. Третьему человеку нужна роль RD Session Host с лицензиями CAL — отдельные деньги и отдельная настройка — либо второй сервер. Учитывать при планировании команды.

### Локация

Выбирается по §1. С настроенным Proxifier физическое расположение сервера на исходящий трафик не влияет — наружу виден IP прокси. Без прокси локация и есть твой исходящий адрес, и тогда она определяет всё.

Практика: боевые машины — зарубежная локация без прокси; тестовые — российская с прокси.

### При заказе

1. Раздел **Cloud Servers**, не shared-хостинг.
2. ОС: **Windows Server 2022**.
3. Публичный IP: **включён** (без него не зайти по RDP).
4. Ничего из managed-услуг и дополнительных IP.
5. Срок: месяц, на пробу.

Через 5–10 минут в панели появятся IPv4, логин `Administrator` и одноразовый пароль.

## §4. Первый заход на сервер

Зайти по RDP под `Administrator`. Сразу:

1. **Сменить пароль** — `Ctrl+Alt+End` → Change password. Длинный.
2. **Скачать Chrome** через Edge.
3. **Скачать Proxifier** с официального сайта — Standard Edition, триал 31 день, лицензия $39.95 разово на машину. *Пропустить, если по §1 прокси не нужен.*

> ⚠️ **Пока Proxifier не настроен, не логиниться на сервере в рабочие аккаунты сервисов.** IP машины попадёт к ним в логи как твой обычный адрес входа, и потом каждая смена IP будет вызывать подтверждения. Остальное из этой серии — в §5.6.

## §5. Proxifier

*Пропустить, если по §1 прокси не нужен.*

Установка обычная: Next → Install. Драйвер ставится вместе с программой и требует прав администратора — это единственный момент, где они нужны. Дальше пять шагов, порядок важен.

### §5.1. Добавить прокси

`Profile → Proxy Servers → Add`

| Поле | Значение |
|---|---|
| Address | IP из §2 |
| Port | порт из §2 |
| Protocol | **HTTPS** (не SOCKS) |
| Use authentication | ✓, логин и пароль из §2 |

Нажать **Check** и дождаться `Test passed`.

Не пропускай Check: он ловит опечатку в пароле **до** того, как ты заворотишь в этот прокси весь трафик машины.

### §5.2. Правило для всего трафика

`Profile → Proxification Rules → Default rule → Edit → Action: Proxy HTTPS [твой прокси]`

> ⚠️ **Правило для localhost, которое стоит выше дефолтного, не трогать.**
>
> Оно единственное, что держит RDP-соединение. Завернёшь его в прокси — потеряешь доступ к серверу и будешь восстанавливать через консоль в панели провайдера. Самая дорогая ошибка этого слоя.

### §5.3. Защита от утечек

`Profile → Advanced`

| Настройка | Значение |
|---|---|
| **DNS and IP Leak Prevention Mode** | ✓ включить |
| Bypass UDP Traffic | переключить на **Block Traffic to All UDP Ports if Matched the Rule** |
| Block Non A/AAAA Queries if DNS through Proxy | ✓ |
| Handle Direct Connections | ✓ (обычно уже стоит) |
| Infinite Connection / Name Resolution Loop Detection | ✓ |

Первая строка — это kill switch: всё, что пытается пойти мимо прокси, блокируется на уровне сетевого стека. Если прокси ляжет, трафик остановится, а не пойдёт напрямую.

Блокировка UDP закрывает утечки через WebRTC и QUIC.

### §5.4. DNS через прокси

`Profile → Name Resolution → ✓ Resolve hostnames through proxy`

Без этого IP у тебя будет чужой, а DNS-запросы — свои. Это видно в тесте из §7.

### §5.5. Автозапуск

`Settings`

- ✓ **Start with Windows**
- ✓ **Hide on close**

Второе важнее, чем кажется: без него Proxifier однажды закроется крестиком, и машина останется без защиты ровно до того момента, когда ты это заметишь. С галкой крестик сворачивает в трей.

### §5.6. Чего не делать

Четыре правила, каждое стоило отдельного вечера.

| Не делать | Почему |
|---|---|
| **Логиниться в рабочие аккаунты до настройки Proxifier** | IP машины попадёт в их логи как твой обычный адрес входа (см. §4) |
| **Работать с упавшим Proxifier** | Иконка в трее неактивна — трафик идёт напрямую. Kill switch из §5.3 это закрывает, но смотреть на иконку всё равно стоит |
| **Брать обычный VPN вместо резидентского прокси** | NordVPN, ProtonVPN и прочие дают датацентровые IP из общих пулов: зашарены на тысячи людей, половина в чёрных списках, капчи там, где их быть не должно |
| **Менять локацию прокси после настройки** | Смена страны рвёт все залогиненные на сервере сессии — разлогины и повторные подтверждения по всему списку сервисов сразу. Локация выбирается один раз |

## §6. Настройки Windows

### Электропитание — не давать серверу засыпать

`Control Panel → Power Options → High performance → Change advanced power settings`

| Параметр | Значение |
|---|---|
| Hard disk → Turn off after | Never |
| Sleep | Never |
| Display | Never |

**Критично для фоновой работы.** Иначе ночью сервер заснёт вместе с твоей задачей.

### Не вырубать RDP-сессию по таймауту

`Win+R → gpedit.msc → Computer Configuration → Administrative Templates → Windows Components → Remote Desktop Services → Remote Desktop Session Host → Session Time Limits`

Все три — в **Disabled**:

- Set time limit for active but idle Remote Desktop Services sessions
- Set time limit for active Remote Desktop Services sessions
- Set time limit for disconnected sessions

Последний особенно: он отвечает за то, чтобы отключённая сессия (и запущенный в ней Proxifier с твоими задачами) продолжала жить.

### Две одновременные сессии

**Ничего настраивать не нужно.** Две разные учётные записи получают по своей RDP-сессии из коробки — это встроенный режим Remote Desktop for Administration. Потолок всё равно два (см. §3).

Групповая политика `Connections → Restrict Remote Desktop Services users to a single session` относится к другому случаю — когда **один и тот же** пользователь хочет две сессии одновременно. Для схемы «админ + рабочий пользователь» её трогать не надо.

Посмотреть, кто сейчас в системе:

```powershell
query session
```

### Часовой пояс

`Settings → Time & Language → Date & Time`

Выставить ту зону, в которой реально работаешь. Set time automatically: On.

Это не косметика: таймзона сервера попадает в логи, в даты коммитов и в расписания задач. Когда через месяц разбираешь, почему ночная задача отработала «не тогда», неверная таймзона стоит час жизни.

### Язык системы

Английский. Не из эстетики — текст ошибки на английском гуглится, на русском нет. Русский можно оставить вторым в Preferred languages для печати.

### Отложить обновления

`Settings → Windows Update → Advanced options → Pause updates` на максимум.

Чтобы автообновление не перезагрузило сервер посреди работы.

### Телеметрия

`Settings → Privacy & Security → Diagnostics & feedback` → Diagnostic data: Required only, остальное Off.

## §7. Проверка слоя

**Перезагрузить сервер.** Дождаться полной загрузки. Если используешь прокси — убедиться, что иконка Proxifier в трее активна.

### Без прокси

Достаточно одного теста:

| Тест | Что должно быть |
|---|---|
| `ifconfig.me` | IP сервера из панели провайдера, страна — та, что заказывал |

Это самый «голый» сервис: показывает ровно тот IP, с которого пришёл запрос. Именно так тебя видит любой сайт. Заодно зайти на те сервисы, с которыми реально работаешь, и убедиться, что они открываются — это и был смысл выбора локации.

### С прокси

| Тест | Что должно быть |
|---|---|
| `ifconfig.me` или `ipinfo.io` | IP прокси, не сервера |
| `whoer.net` | IP, страна и провайдер — те, что у прокси |
| `browserleaks.com/webrtc` | WebRTC Leak Test: **No Leak**; Local IP и Public IP пустые |
| `dnsleaktest.com` → Standard test | DNS-серверы в той же стране, что прокси; посторонних нет |

### Командой

```powershell
(Invoke-RestMethod https://api.ipify.org?format=json).ip
```

С прокси должен вывести IP прокси, без прокси — IP сервера из панели провайдера.

---

> ⚠️ **Если хоть один тест показывает не тот IP или утечку — слой не пройден.**
>
> Не иди дальше. Всё, что поставишь сверху, будет ходить наружу неправильным путём, и чинить это потом сложнее, чем сейчас. Типичные причины — в [`../TROUBLESHOOTING.md`](../TROUBLESHOOTING.md), раздел «Сеть и Proxifier».
